# Mellyn Security Runtime Gateway — Threat Model

**Scope**: Plane 3 — Self-Hosted MCP Tool-Call Authorizer & Gateway (`backend/mellyn/`).
**Deployment Model (v1)**: Single-tenant, self-hosted container stack or local stdio gateway running inside the customer's VPC or developer workstation.
**Status legend**: controls marked *(planned)* are design commitments that the code does not implement yet.

---

## 1. Assets & Trust Boundaries

### Critical Assets
1. **Authorization Policy, Capability Bindings & MCP Allowlist**: Determines which servers, tools, arguments, and network destinations an agent may invoke.
2. **Session Taint State & Human Grants**: Tracks whether untrusted external data has entered a session and stores short-lived approvals for exact calls.
3. **Audit Logs**: Redacted structured record of every tool-call authorization decision, taint event, and risk signal.
4. **API Credentials**: The **agent key** (held by the agent harness) and the **approver key** (held only by the human approval surface), stored server-side as `HMAC-SHA256(pepper, key)` digests.

### Trust Boundaries
```text
[ Untrusted External Data: Web, Issues, PRs, 3rd-Party MCP Responses ]
        │  (Boundary 1: Session becomes TAINTED — automatically when an allowed call returns
        │   external content or an unpinned untrusted MCP server lists tools/resources)
        ▼
[ AI Agent / LLM Runtime (Probabilistic, Assumed Prompt-Injectable) ]
        │  (Boundary 2: Gateway intercepts inline over stdio; or harness submits with agent key)
        ▼
[ Mellyn Security Authorizer Core (Capabilities + Policy + Taint + Exact-Call Grants) ] ◄── Approver key (humans only)
        │  (Boundary 3: Workspace path jail + egress URL checks; Squid egress proxy in container stack)
        ▼
[ Downstream MCP Servers / Local Shell / Internal APIs / Cloud ]
```

**Core Assumption**: The LLM and agent loop are **inside the blast radius of indirect prompt injection**. Security guarantees must hold even when the model is actively trying to invoke unauthorized tools or exfiltrate secrets.

**Integration modes**:
- **stdio MCP gateway** (`mcp_gateway.py`): the MCP client launches the gateway instead of its servers, and the gateway launches the servers as child processes (`shell=False`, `MELLYN_*` secrets stripped). Every tool call and resource read passes through the authorizer inline. One gateway process fronts all of the client's servers so they share one session. Remove the servers from the client's own MCP config so no direct route remains.
- **HTTP API** (`api.py`): a custom harness calls `/v1/agent/authorize` before running each tool. It protects only tool calls the harness submits, and the agent key must not be reachable from the agent's own tools.

## 2. Deployment & Operational Decisions

| Decision | v1 Choice (Self-Hosted) | Security Rationale |
| :--- | :--- | :--- |
| **Tenancy & Isolation** | **Single-tenant per deployment** (1 container stack / VPC per SMB customer). | Eliminates cross-tenant data leakage, shared-memory side channels, and multi-tenant SOC 2 custody of raw prompts/secrets. |
| **Credentials** | **Two keys, two roles.** The agent key can create sessions, report taint, and request decisions. Only the approver key can issue grants. The HTTP API answers `503` if keys are missing or identical. | An agent or harness holding the agent credential can never approve its own calls. |
| **Session State** | **Server-issued session IDs**; unknown or expired IDs are denied, and hitting `max_sessions` refuses new sessions rather than evicting active ones. Optional `SqliteStateStore` (`MELLYN_STATE_DB_PATH`, enabled in containers) persists sessions, taint, and single-use grants across restarts and fails closed on DB corruption. | Prevents taint laundering via invented IDs or process restarts, fail-open resets, and session-eviction DoS. |
| **Audit Log Content** | **Redacted structured metadata only** (decision, tool name, MCP server, SHA-256 argument hash, redacted taint sources & reasons). Raw prompts and secret values are never persisted. | Prevents the audit log from becoming a secondary credential/PII store. Argument hashes are unsalted, so treat the log as confidential. Retention is customer-controlled *(planned: 30–90 day default)*. |
| **Failure Mode** | **Fail closed**: unknown tool → `HIGH`, unknown session → `DENY`, unguarded `LOW`/`MEDIUM` policy entry → `PolicyLoadError`, missing API credentials → `503`. In HTTP API mode, harnesses must also treat network/timeout errors from the authorizer as `DENY`. | Crashes, timeouts, or misconfigurations never grant silent shell, file, or network access. |
| **Approval Grants** | **One exact call**: bound to session, tool, MCP server, and canonical RFC 8259 JSON arguments; expires (default 15 min, max 24 h); single-use unless `max_uses` is set. | Approving `git_push(branch="feature/x")` can never authorize `feature/x:main` or an added `force=True`. |

## 4. Residual Risks (Accepted or Open)

- **Running tests executes workspace code.** A taint-safe rule for `pytest` runs whatever code is in the workspace. This is acceptable only because writes in a tainted session require approval; an approver who approves a write is approving code that the test rule will later run.
- **Deny rules and inline-eval checks narrow approvals; they are not a sandbox.** `validate_argv` blocks shell interpreters and inline evaluation flags (`python -c`, `node -e`, `perl -e`, `git -c`, `find -exec`, ...), but an approved `HIGH`-risk command can still invoke build scripts (`make`, `npm run`). High-risk defaults to human approval.
- **Check-then-use on paths (TOCTOU).** The authorizer validates a path before the downstream tool opens it; a symlink swapped in between check and open is not caught unless tools open with `O_NOFOLLOW` or the gateway performs file I/O directly *(planned)*.
- **Egress outside the container stack.** Tools running directly on a developer workstation receive application-layer URL checks only; network-layer DNS-rebinding protection requires the `deploy/` Squid container topology.
- **Workspace mount requirement.** Symlink resolution requires seeing the agent's real filesystem (`MELLYN_REQUIRE_WORKSPACE_MOUNT=1` enforces this in containers).
- **Per-connection stdio gateway & pending approval state.** While the HTTP authorizer API (`api.py`) persists sessions, taint provenance, and issued grants in SQLite when `MELLYN_STATE_DB_PATH` is set, the stdio MCP gateway (`mcp_gateway.py`) holds live per-connection session state and pending approval queues in memory; stopping the gateway process clears pending calls fail-closed.
- **The state database is part of the authorizer's trust boundary.** Anyone who can write `MELLYN_STATE_DB_PATH` can clear taint or mint grants, so protect it like the authorizer itself: the store creates its folder `0700` and its files `0600` from the start, and refuses to open a database containing any object it did not create (a planted trigger or view would otherwise keep rewriting state after every restart). Live grants hold the exact approved arguments and the `approved_by` label unredacted, because a grant must match its call exactly; spent and expired grants are deleted rather than kept until their session expires.
- **Gateway scanner, AAD containment, and observe mode.** The gateway scans `tools/call` and `resources/read` requests and responses, and `tools/list` / `resources/list` listings, for canaries, known secrets, and configured patterns, at any nesting depth; a payload nested past 64 levels is blocked outright. A canary severs the whole session, as in the Airlock: every downstream server is stopped and every later call is refused. Observe mode needs both `--mode observe` and `[runtime].allow_observe_mode = true` (the config alone never selects it). It lets approval-required calls and scanner hits through and logs each one, but never relaxes a DENY, so an observe session cannot rewrite the gateway's own config, audit log, or state, or reach secret files. Audit reasons carry rule IDs only, never a hash of the matched value. Tool and resource definitions containing invisible Unicode format/tag characters are refused by `mellyn pin` and blocked when listed, pinned or not: a pin records a hash, it does not make hidden instructions safe, and pinned descriptions are not tainted. Audit-log lines escape U+2028, U+2029 and U+0085 and are split on newlines only, so caller-supplied text cannot split a record and break the chain. The gateway's scanner (`backend/mellyn/scanner.py`) is still a port of the Airlock's detection; a parity test keeps the two in step until they share one implementation *(planned)*.
- **Name-guessed path arguments on unbound `HIGH` tools.** Unbound tools fall back to checking common path argument names (`path`, `file`, `source`, `destination`, ...); custom nested schemas should declare an explicit `ToolCapability`.
- **Self-declared `approved_by` string.** Possession of the approver key is cryptographically verified, while the `approved_by` label is self-reported until per-user SSO is added *(planned)*.

## 5. Non-Goals (Explicitly Out of Scope for v1)
- **Detecting 100% of prompt injections in free-form text**: Handled as an escalate-only supporting signal, never an allow gate.
- **Multi-tenant SaaS prompt storage**: Deferred so SMB deployments retain zero third-party prompt custody.
- **OS kernel sandboxing**: Mellyn Security enforces tool-call authorization and egress controls; OS/container isolation remains a complementary Layer 1/infrastructure control.

## 6. MCP Airlock Containment Plane (`src/mcp_airlock/`)

While Sections 1–5 cover the multi-server taint-tracking control plane in `backend/mellyn/`, **`mcp_airlock` (`src/mcp_airlock/`)** provides a zero-dependency (`pydantic`-only) single-server stdio containment airlock (`mellyn-airlock`), quarantined manifest pinner (`mellyn-pin`), scanner benchmark (`mellyn-bench`), and cryptographic incident reconstructor (`mellyn-ir`).

| Airlock Control ID | Threat / Bypass Target | Airlock Mechanism |
| :--- | :--- | :--- |
| **AL-01** | **AgBOM Rug-Pulls, Instruction Injection & Hidden Unicode** | `mellyn-pin` and `verify_tools_list()` compute SHA-256 digests over exact canonical wire JSON for every tool definition (plus optional `manifest_sha256` and `initialize.instructions_sha256`). Any tool mutation, unpinned tool, or invisible Unicode tag/zero-width/bidi injection triggers immediate `AAD_FIRE` containment (exit code `78`), while unpinned `instructions` and extra `tools/list` keys are stripped. |
| **AL-02** | **Obfuscated & Encoded Canary / Secret Exfiltration** | `egress.scanner` and `core.audit` compute `artifact_sha256` on exact forwarded bytes first, then detect and redact raw, casefolded, invisible-tag/ZWSP-interleaved, NFKC-homoglyphed, double-percent-encoded, reversed, separator-interleaved (`C.A.N.A.R.Y`), contiguous/delimited hex, and Base64/Base64url (all 3 byte-alignment offsets) canary tokens, known API/cloud secrets, and high-entropy blobs before forwarding or persisting telemetry. |
| **AL-03** | **Automatic Activation Device (AAD) & Containment Attestation** | On `AAD_FIRE`, `AirlockProxy._trigger_aad` synchronously fsyncs the redacted trigger `ZoneEvent`, severs downstream stdin, hard-kills the downstream process group (`os.killpg` + Linux `PR_SET_PDEATHSIG`) or Windows Kill-on-Close Job Object, awaits process reap, appends a linked `airlock.aad_containment_confirmed` completion receipt, and only then sends `-32099` (`AAD_CONTAINMENT_SEVERED`). `mellyn-ir` distinguishes `AAD_CONTAINED` from `AAD_TRIGGERED_UNCONFIRMED`. |
| **AL-04** | **Tamper-Evident Flight Recorder & External Anchoring** | `AuditLedger` refuses to open or append onto a tampered ledger, holds an exclusive OS lock across appends, asserts zero canary survival pre-flush, and chains canonical entries from `GENESIS_PREV_HASH` (`"0" * 64`). `mellyn-ir` checks the full hash chain and optional external `(seq, entry_hash)` tail-truncation anchors from a single verified byte snapshot before rendering sanitized reports. |
| **AL-05** | **DoS Framing Bombs, Spoofed Response IDs & Oracle Leakage** | `BoundedLineReader` and `BoundedStdinReader` (`65,536` B read-ahead budget) drop oversized single-line frames before JSON parsing; duplicate-key JSON objects, non-finite floats, lone surrogates, unsolicited response IDs, expired timeout IDs, and stale pagination cursors fail closed. Optional `--opaque-policy-errors` masks `rule_id` and regex details on client `-32000` frames while keeping full forensics in `AuditLedger`. |
| **AL-06** | **Quarantined Red-Team Harness (`--mode observe`) Isolation** | Observe mode forwards every policy violation and never fires the kill, so it needs two independent opt-ins: the operator CLI flag (`--mode observe`; a policy cannot set the mode itself, `extra="forbid"`) **and** `allow_observe_mode = true` in the reviewed `AirlockPolicy`. Editing an MCP client's launch command alone cannot switch enforcement off. Every session's first ledger record (`airlock.session_started`) states its mode and flags, observe sessions print a stderr warning, and `mellyn-ir` shows each session's mode and classifies observe-only sessions as `OBSERVED_VIOLATIONS`. Even in observe mode, protocol framing caps, malformed frame rejection, request-ID bounds, child env isolation, and timeouts remain hard-enforced. |
